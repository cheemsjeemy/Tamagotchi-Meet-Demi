# Plan: Implement MS Authenticator TOTP with NTP Time Sync

## Goal
Integrate Time-based One-Time Password (TOTP) generation compatible with Microsoft Authenticator into the ESP32 menu system using a provided MS Authenticator secret. Use NTP from pool.ntp.org for accurate time synchronization. Follow Luca Dentella's TOTP implementation style with uint8_t hmacKey[] and keyLength.

## Requirements
- Use Luca Dentella's TOTP approach: uint8_t hmacKey[] array for the key, with keyLength = 10 (bytes)
- Add NTP time sync using configTime() with pool.ntp.org for Philippines servers
- On startup, prompt for or load the MS Authenticator secret (provided by user later)
- If no secret loaded, enter setup mode to input/display the provided secret
- Store secret permanently in Preferences (persists across reboots until manually cleared)
- Compute and display current TOTP code on OLED with custom formatting
- Handle menu navigation and display states

## Implementation Steps

### 1. Add NTP Synchronization
- Use ESP32's built-in `configTime()` function with `pool.ntp.org`
- Call `configTime("pool.ntp.org", 0, 0, 0, 0);` in setup for automatic NTP sync every hour
- Ensure WiFi remains connected for sync
- TOTP uses UTC time, so no timezone offset needed

### 2. Integrate TOTP Library/Implementation
- Follow Luca Dentella's TOTP style: use uint8_t hmacKey[] for binary key storage
- Set keyLength to 10 bytes (as per user's specification)
- On startup, load hmacKey and keyLength from Preferences
- If loaded, create TOTP instance immediately
- Update TOTP code every 30 seconds in menu render loop
- Implement TOTP calculation using HMAC-SHA1 with the binary key

### 3. Implement MSAuth Callback (cbMSAuth)
- Check Preferences for existing hmacKey on first run
- If no key exists, enter setup mode to receive user-provided MS Authenticator secret (hex format)
- Once secret provided, convert hex string to binary format and store in hmacKey array (length 10 bytes)
- Save to Preferences permanently
- On subsequent calls, display TOTP code screen directly

### 4. Secret Input/Setup Mode
- User provides MS Authenticator secret in hex format (20 characters)
- Implement serial input handling for secret entry during setup
- Convert provided hex string to binary format for hmacKey (each pair of hex chars = 1 byte, total 20 hex chars for 10 bytes)
- Ensure keyLength = 10 bytes

### 5. OLED Display for TOTP Code
- Modify renderMenu() to show TOTP code when active (full screen overlay)
- Display code in large bold font with spaces: e.g., "123 456"
- Add countdown progress bar at bottom of screen
- Show mini timer at center top of progress bar: e.g., "30s" (counts down from 30 to 0)
- Add tiny status icons: WiFi connected and NTP synced indicators

### 6. Persistence and Security
- Save hmacKey (as hex string) to Preferences immediately after setup
- Load on startup in initMenu()
- Secret remains until manually cleared

### 7. Menu Integration
- Link MSAuth action to cbMSAuth
- Handle enter/back navigation for TOTP display
- Add visual feedback (beeps, redraws)

### 8. Testing and Validation
- Verify NTP sync and accurate time
- Test TOTP code matches MS Authenticator using provided secret
- Handle edge cases (no internet, time drift)

## Dependencies
- TOTP library (already installed, using Luca Dentella style with uint8_t hmacKey[] and keyLength)
- ESP32 Arduino core with WiFi/NTP support

## Potential Challenges
- Converting provided MS Authenticator secret to uint8_t hmacKey[10] format
- Ensuring compatibility with MS Authenticator (secret provided by user)
- NTP sync reliability
- Custom OLED formatting
